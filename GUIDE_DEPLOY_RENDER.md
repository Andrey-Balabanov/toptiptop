## 1. Подготовка репозитория на GitHub

### 1.1. Создайте репозиторий

1. Зайдите на GitHub, нажмите **+** → **New repository**.
2. Название: `toptiptop`.
3. **Public** (Render должен видеть код).
4. Не ставьте галочку «Initialize with README».
5. Нажмите **Create repository**.

### 1.2. Подготовьте файлы в корне проекта

#### `.gitignore`

Создайте файл `.gitignore` в корне проекта:

```
node_modules/
.env
data/
*.db
.DS_Store
```

#### `.env` — только для локальной разработки

> ⚠️ **Важно понимать:** файл `.env` **не загружается на GitHub** (он в `.gitignore`)
> и **не попадает на Render**. На Render переменные задаются **вручную в дашборде**
> (раздел [2.3](#23-переменные-окружения-environment-variables)), а `.env` нужен
> **только** для запуска проекта у вас на компьютере.

Файл `.env` лежит в **корне проекта** (рядом с `server.js`) и является **скрытым**
(dotfile) — поэтому вы можете его не видеть. Проверить его наличие:

```bash
ls -la .env        # macOS / Linux  → должен показать файл
dir /a .env        # Windows
```

Если файла нет — создайте из шаблона: `cp .env.example .env` (и подставьте свои значения).

Содержимое `.env` должно быть таким (или своим):

```env
JWT_SECRET=мой-супер-секретный-ключ-12345
JWT_EXPIRES_IN=7d
DB_PATH=./data/toptiptop.db
DEV_AUTO_VERIFY=true
```

> 💡 Строка `PORT=3001` в `.env` **не мешает** деплою: `.env` не попадает на Render,
> а на хостинге `process.env.PORT` задаёт сам Render (он приоритетнее — `dotenv`
> не перезаписывает уже установленные переменные). Локально `PORT=3001` можно оставить.

> ⚠️ **JWT_SECRET обязательно должен быть уникальным.** В коде есть защита: если в production режиме секрет равен `dev-secret-change-me`, сервер аварийно завершится при запуске.

> **DEV_AUTO_VERIFY=true** — пропускает email-подтверждение (регистрация проходит мгновенно). Если хотите реальную верификацию по email — настройте SMTP (см. раздел 6) и удалите эту переменную.

### 1.3. Загрузите код на GitHub

```bash
git init
git add .
git commit -m "Первый коммит"

git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/toptiptop.git
git push -u origin main
```

> 🔑 При `git push` потребуется **Personal Access Token** (не пароль):  
> GitHub → **Settings** → **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token** → поставьте галочку **repo** → скопируйте токен.

> ✅ Проверка перед push: `git status` **не должен** содержать `.env` (он игнорируется автоматически — так и должно быть).

## 2. Создание Web Service на Render

### 2.1. Зайдите на [render.com](https://render.com)

Нажмите **Sign up with GitHub** → подтвердите доступ к репозиториям.

### 2.2. Нажмите **New +** → **Web Service**

Выберите репозиторий `toptiptop` и заполните:

| Поле | Значение | Комментарий |
|------|----------|-------------|
| **Name** | `toptiptop` | URL будет `https://toptiptop.onrender.com` |
| **Region** | `Frankfurt (EU)` | Ближайший к Европе/России |
| **Branch** | `main` | Ветка для деплоя |
| **Runtime** | `Node` | Определяется автоматически |
| **Build Command** | `npm install` | Установка зависимостей |
| **Start Command** | `npm start` | Запускает `node server.js` |
| **Plan** | **Free** | Бесплатно (750 часов/мес) |

### 2.3. Переменные окружения (Environment Variables)

> 🔽 **Здесь вместо `.env`.** На Render файла `.env` нет и не будет — переменные
> задаются прямо в дашборде. Это и есть «продовый `.env`».

Прокрутите вниз до раздела **Environment Variables**, нажмите **Add Environment Variable** и добавьте:

| Key | Value | Обязательно? | Зачем |
|-----|-------|:---:|-------|
| `JWT_SECRET` | Ваш длинный случайный секрет | ✅ **Да** | Без него токены не переживут рестарт |
| `JWT_EXPIRES_IN` | `7d` | ✅ Да | Срок действия токена |
| `DB_PATH` | `./data/toptiptop.db` | ✅ Да | Путь к SQLite-базе |
| `ADMIN_EMAIL` | ваш реальный email | ✅ Да | Логин в админ-панель |
| `ADMIN_PASSWORD` | надёжный пароль | ✅ Да | Пароль админа (создаётся при старте) |
| `DEV_AUTO_VERIFY` | `true` | ❓ **Рекомендуется** | Пропускает email-подтверждение |
| `NODE_ENV` | `production` | ❓ По желанию | Включает production-режим |

> ❌ **НЕ добавляйте `PORT`** — Render устанавливает его автоматически. Код в `src/config.js` читает `process.env.PORT || 3001`, поэтому всё работает.

Полный список всех переменных (включая `MAIL_*`, `TRUST_PROXY`, `FRONTEND_URL`) —
в **[ENV_REFERENCE.md](ENV_REFERENCE.md)**.

### 2.4. Нажмите **Create Web Service**

Сборка занимает 2–5 минут. После успешного деплоя будет доступно:

```
https://toptiptop.onrender.com
```

## 5. ⚠️ Особенности бесплатного тарифа

### 5.1. Режим сна (Spindown)

Render выключает сервер после **15 минут** бездействия. При первом заходе после сна — ожидание **30–50 секунд** (сервер пробуждается).

> Отключить сон можно только на платном тарифе ($7/мес).

### 5.2. SQLite — данные НЕ сохраняются при деплое

**Это самая важная особенность.** На бесплатном тарифе Render использует **эфемерный диск**:

| Событие | Что происходит с БД |
|---------|-------------------|
| Перезапуск сервера | ✅ Данные сохраняются |
| Переход в режим сна и пробуждение | ✅ Данные сохраняются |
| **Новый деплой (git push)** | ❌ **Все данные теряются** |
| Автоматический переезд на другой сервер | ❌ Данные теряются |

**Последствия:** пользователи, сохранённые тренировки, XP, достижения — всё пропадает при каждом `git push`.

### 5.3. Решения для базы данных в продакшне

| Сервис | Тип БД | Бесплатно |
|--------|--------|:---------:|
| [Supabase](https://supabase.com) | PostgreSQL | 500 MB |
| [Railway](https://railway.app) | PostgreSQL | $5 кредита/мес |
| [ElephantSQL](https://www.elephantsql.com) | PostgreSQL | 20 MB |

> Для перехода на PostgreSQL потребуется заменить `better-sqlite3` на `pg` в `src/db.js` и адаптировать SQL-запросы — это отдельная задача.

## 6. Настройка email (опционально)

Если вы не хотите использовать `DEV_AUTO_VERIFY=true` (авто-верификация), настройте SMTP.

Добавьте на Render переменные окружения (пример для Яндекс.Почты):

| Key | Value |
|-----|-------|
| `MAIL_HOST` | `smtp.yandex.ru` |
| `MAIL_PORT` | `587` |
| `MAIL_USER` | `your@yandex.ru` |
| `MAIL_PASS` | `ваш-пароль-приложения` |
| `MAIL_FROM` | `your@yandex.ru` |

> 🔑 Для Яндекс.Почты нужен **пароль приложения** (не обычный пароль):  
> Яндекс.Почта → **Настройки** → **Безопасность** → **Пароли приложений**

После настройки SMTP — **удалите** переменную `DEV_AUTO_VERIFY=true` или измените её на `false`.

## 7. Частые проблемы и решения

### ❌ Не могу найти файл `.env`

**Симптом:** в корне проекта нет файла `.env`, `ls` его не показывает, на GitHub его нет.

**Причина — это нормально, и есть две причины сразу:**

1. **`.env` — это скрытый файл (dotfile).** Имя начинается с точки `.`, поэтому Finder (macOS) и Проводник (Windows) его прячут, а `ls` без флагов не показывает.
2. **`.env` исключён из git** (строка `.env` в `.gitignore`) — поэтому его нет ни в репозитории на GitHub, ни на Render. Это защита секретов.

**Решение — как найти или создать:**

| Ситуация | Что делать |
|----------|-----------|
| Файл есть, но «не видно» | **macOS (Finder):** `Cmd + Shift + .` (точка). **Windows:** Вид → галка «Скрытые элементы». **Терминал:** `ls -la` (покажет `.env`) |
| Файла нет (свежий клон репозитория) | `cp .env.example .env` (macOS/Linux) или `copy .env.example .env` (Windows), затем впишите свои значения |
| Не можете найти `.env` на Render | ✅ **Правильно — там его нет.** На Render переменные задаются в **Dashboard → Environment Variables** (см. раздел 2.3) |
| Windows + Блокнот | Сохраняйте через **«Файл → Сохранить как» → «Тип файла: Все файлы»**, иначе получится `.env.txt` — сервер его не увидит |

> 📖 Подробнее: **[ENV_REFERENCE.md](ENV_REFERENCE.md)** → «Где лежит `.env` и почему его не видно».

### ❌ Сервер не запускается, в логах ошибка

```
CRITICAL: JWT_SECRET is set to the insecure default in production!
```

**Причина:** Не указан `JWT_SECRET` в переменных окружения Render.  
**Решение:** Добавьте `JWT_SECRET` с уникальным значением → **Manual Deploy** → **Deploy latest commit**.

### ❌ 502 Bad Gateway

**Причина:** Сервер упал или не успел запуститься за отведённое время (90 секунд на бесплатном тарифе).  
**Решение:** Проверьте логи в Render Dashboard (вкладка **Logs**).

### ❌ Ошибка 500 при регистрации

**Причина:** База данных не может быть создана — нет прав на запись.  
**Решение:** Убедитесь, что `DB_PATH=./data/toptiptop.db` (директория `./data` будет создана автоматически).

### ❌ Пустая страница или 404

**Причина:** Не найден `public/index.html`.  
**Решение:** Проверьте, что папка `public/` с файлом `index.html` есть в репозитории (запушена на GitHub).

### ❌ Ошибка «Слишком много запросов»

**Причина:** Сработал rate limiter (20 запросов за 15 минут для `/api/auth` или 200 для `/api`).  
**Решение:** Подождите 15 минут.

### ❌ Не приходит письмо с кодом (если настроен SMTP)

**Причина:** Неверные SMTP-настройки или письмо попало в спам.  
**Решение:** Проверьте логи на Render — ошибки SMTP видны там. Проверьте папку Спам.
